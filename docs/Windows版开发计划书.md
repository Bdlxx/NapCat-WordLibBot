## 1. 项目背景与目标

### 1.1 背景

当前项目为基于 Python 的 QQ 机器人框架，运行于 Linux 服务器，通过 NapCat（OneBot v11）接入 QQ，插件为纯 Python 模块，管理界面为 Flask Web 面板。

计划将其移植/重构成 **Windows 桌面版**，面向普通用户，降低使用门槛（双击即用、免命令行、免 Linux 环境）。

### 1.2 目标

| 目标 | 说明 |
|---|---|
| 双击即用 | 单 zip 分发，解压即运行，无需安装 Python/Node |
| 免命令行登录 | 首启向导引导选择运行方式并扫码登录 |
| 多账号 | 一个主程序同时管理多个 QQ |
| 插件生态开放 | 支持 Python（.py/.pyd）与原生语言（DLL）插件 |
| 后端可插拔 | 不绑定 NapCat，支持多协议后端（内置协议/小栗子等） |
| 防小白乱改 | 插件发布形态为二进制（.pyd），避免误改导致崩溃 |
| 自动更新 | 启动检查更新，zip 增量替换，保留用户数据 |

## 3. 首启向导（First-Run Wizard）

双击 AsterCore.exe → 检测 `data/runtime.json`：

- 已配置 → 直接启动（正常模式）
- 首次 → 向导三步：

### 步骤 1 · 选择运行方式

| 选项 | 形态 | 安全评级 | 说明 |
|---|---|---|---|
| **A. NapCat 稳定模式（推荐）** | 后台运行官方 QQ 客户端 + NapCat 中间层 | ★★★★★ | 走官方登录通道，风控风险最低 |
| **B. 内置协议直登（Lagrange）** | 纯协议实现，无需安装任何客户端 | ★★☆ | 双击扫码即用；非官方协议存在**账号风控/封号风险**，建议小号 |

### 步骤 2 · 安全等级说明（风险透明）

- 固定文案告知：B 模式为非官方通道，存在限制登录/封号风险，项目不承担损失
- 建议 B 模式仅用于测试/小号；正式使用选 A
- 勾选"我已知晓风险"后进入下一步（每次选 B 均弹一次）

### 步骤 3 · 登录 & 完成

- 扫码登录（两种方式均支持）
- 生成 runtime.json 记录 mode + risk_acknowledged
- 后续可在 面板 → 设置 → 运行方式 中随时切换（提示将中断当前连接）


### 3.1 NapCat 连接引导（引导下载 · 零手动配置为主）

- **场景 A（主路径）**：引导下载 → 程序自动写 NapCat 配置（onebot11.json：127.0.0.1 + 自动端口 + 自动 token）→ 扫码登录 → bot 自动连接，用户零配置
- **场景 B**：用户已有自装 NapCat → 先「自动发现」本机端点；未找到再手动填三字段（WS/HTTP/token）+ 测试连接
- **场景 C（高级）**：连远程/已有实例，同三字段，地址填远端 IP
- 连接信息存 `accounts/<QQ>/backend.json`（每账号独立）

## 4. 多账号支持

- 每个账号 = 独立目录 `accounts/<QQ>/` + 独立后端实例进程
- 内核同时连接多个后端的 WebSocket
- 统一事件携带 `account_id`；插件数据按账号隔离存储
- 插件分两类：
  - **账号无关**（点歌/视频解析等）—— 不感知账号
  - **账号相关**（签到/结婚/人设/词库）—— 数据键增加账号维度
- 与现 Linux 多实例架构（instances/<QQ>）逻辑一致，迁移成本低

## 4.1 账号管理与页面分层（单端口 · 多页面）

### 入口
- Web 面板侧边栏新增「账号管理」页
- 首页账号卡片区支持 **右键 / "+" 新建账号**

### 新建账号（账号配置页）
| 字段 | 说明 |
|---|---|
| 账号名称 | 显示名（如：依星） |
| 登录 QQ | 扫码登录后自动回填 |
| 连接方式 | NapCat（外部）/ 内置协议直登（实验） |
| WS / HTTP / Token | 预填 127.0.0.1 默认值，手动改端口/token；保存前「测试连接」 |
| 保存 | 写入 `accounts/<QQ>/backend.json`，列表出现账号卡片 |

- 账号列表卡片：启动 / 停止 / 重新登录 / 编辑 / 删除；状态 ●在线 ○离线
- 连接方式可**账号级独立设置**（A 号 NapCat、B 号内置直登），不强制全局一致

### 本地零端口 + 可选 HTTP（多页面分层不变）

**本地面板默认零端口**：pywebview 内嵌加载同一份前端资源，JS 与 Python 走**进程内 bridge**
（直接函数调用，如 `pyapi.get_logs()`），不监听任何 TCP 端口 → 无端口冲突。

**HTTP 服务 = 独立可选模块**（默认关闭，设置里单独开启）：

```
设置 → 远程访问（默认关闭）
├─ 启用 HTTP 服务           [开关]
├─ 监听地址                 127.0.0.1（默认）/ 0.0.0.0
├─ 端口                     （默认 8080，冲突可改）
├─ 连接域名                 （可选，用于反代/提示）
├─ 鉴权                     [本机免密 | 密码 | Token]
└─ 用法提示                 浏览器打开 / 局域网 / 域名+反代+HTTPS
```

启用 HTTP 后的路由分层（同源共享登录态，路径前缀分层，不做虚拟目录/iframe）：

```
http://127.0.0.1:8080
├─ /panel/accounts/…      全局层：账号管理、插件、设置
├─ /account/<QQ>/…        账号层：某账号的仪表盘/配置/日志
└─ /api/…                 统一 JSON API 前缀（鉴权中间件只挂一处）
```

**架构要点**：
- 前端资源**同一份**，渲染载体可变（pywebview 进程内 bridge 或 HTTP）
- 内核 API 抽成"可挂两种暴露方式"：进程内函数调用 + HTTP JSON API
- 现有 Flask 面板在 HTTP 模式原样复用；bridge 模式是新增薄层
- 默认零端口无冲突；远程能力按需开启



### 5.1 三轨并存

| 轨道 | 后缀 | 加载方式 | 用途 |
|---|---|---|---|
| 1 | `.py` | Python import | 内部开发、快速迭代 |
| 2 | `.pyd` | Python import（Cython 编译） | **对外分发防改**（二进制） |
| 3 | `.dll` | ctypes + C-ABI | 易语言/C/C++/Rust 等原生语言 |

### 5.2 Python 插件防改方案（轨道 1/2）

- 保持现有 SDK 接口不变，开发维护 `.py`
- 发布时 Cython 编译为 `.pyd`（= Windows 原生扩展 DLL），用户无法直接打开修改
- 加载器自动优先 `.pyd`（import 机制天然支持）
- 防改级别：防小白乱改；专业逆向另议（可后续加壳）

### 5.3 原生 DLL 插件（轨道 3 · C-ABI）

标准导出（草案，最终以 ABI.md 为准）：

```c
int  nap_plugin_init    (const char* config_json, NapApi* api);
int  nap_plugin_on_event(const char* event_json);      // 0=未处理 1=已处理
void nap_plugin_unload  (void);

typedef struct NapApi {
    int (*send_message)(const char* action_json);      // 统一动作
    void (*log)(int level, const char* msg);
} NapApi;
```

- 全部数据以 **JSON 字符串** 传递（跨语言无结构体对齐问题）
- 动作回调由主程序注入（init 时给到 api 指针）
- 事件 JSON 含 `account_id`

### 5.4 语言模板（SDK 仓库规划）

```
plugin-sdk/
├─ ABI.md                        # 协议规范（唯一权威）
├─ nap_plugin.h                  # 官方 C 头文件
├─ examples/c-sample/            # C 模板（第一优先）
├─ examples/rust-sample/         # Rust 模板（cdylib）
├─ examples/cpp-sample/          # C++ 模板
└─ examples/yiyuyan-sample/      # 易语言模板（第二批）
```

**易语言模板注意事项**（写模板前必须告知用户）：
1. 运行库依赖 `krnln.fnr` 等支持库，需随 DLL 分发或静态编译
2. 字符串用指针传递，入口只收 JSON 指针，内部再转易语言文本
3. 建议 **子进程隔离**（见下）防止插件崩溃带崩主程序

### 5.5 原生插件进程隔离（安全设计）

- Python 插件崩了只影响自身；原生 DLL 野指针会带崩主程序
- 方案：原生 DLL 放入**独立子进程**（host 进程），主程序通过本地 IPC（stdin/stdout JSON 或命名管道）通信
- 插件崩溃 → 子进程退出 → 主程序可重启该插件或标记禁用

## 6. UI 形态

| 场景 | 实现 | 说明 |
|---|---|---|
| 首启向导 | 原生轻窗口（pywebview 或 Tkinter） | 3 步完成，系统级操作原生体验 |
| 主面板 | **pywebview 内嵌 Web**（默认） | 桌面软件窗口感 + 进程内 bridge **零端口**；复用现有 Flask 前端 |
| HTTP/远程 | 可选模块（默认关闭） | 端口/域名/鉴权独立配置（详见 §4.1） |
| 面板页面 | 账号管理 / 账号配置页（新增） | 单端口多页面分层（§4.1），侧边栏 + 右键新建账号 |
| 备选 | 设置里可切"默认浏览器打开" | 习惯浏览器的用户可选 |
| 系统托盘 | 常驻、打开面板、退出、更新提示 | |

**鉴权模式**（web 设置页"安全/远程"分栏，仅 HTTP 模式生效；本地 bridge 天然本机）：

| 模式 | 行为 |
|---|---|
| 本机免密（默认） | 仅监听 127.0.0.1，打开即用 |
| 简单密码 | 首次访问输入，session 记住 |
| Token | 适合程序化/反代场景 |
| 局域网/域名 | 监听 0.0.0.0 + 密码/Token + 建议反代 HTTPS |

## 7. 打包与分发

### 7.1 打包工具

- **PyInstaller（--onedir）**：主方案，成熟稳定
- Nuitka：备选（体积小、性能好但编译慢），可在 CI 中实验

### 7.2 构建平台

- Windows 上构建（Python 无交叉编译）；用 GitHub Actions `windows-latest` runner 自动化
- 构建产物 = 单个 zip：`NapBot-v1.2.0-win64.zip`

### 7.3 NapCat 组件策略

- **不强制捆绑**：可选组件；引导下载为主，程序自动写配置（详见 §3.1 三场景），避免用户手填
- 未检测到 NapCat → 界面内"下载并安装 NapCat"引导（拉官方包解压到 napcat/）
- 更新器将 NapCat 视为可选组件，可单独更新
- 理由：NapCat 强依赖 NTQQ 版本，固定捆绑易随 QQ 更新失效；再分发需确认其许可证

### 7.3.1 分发目标（已定）

- 自用 + 小范围朋友：**zip 分发**即可
- 不强制代码签名与安装器（首版）；如后续对外再补
- 更新源：GitHub Releases 或内网静态目录（二选一，后续定）

### 7.4 更新器

- 启动后台检查更新源（GitHub Releases / 自建静态服务器）
- 下载 zip → **哈希/签名校验** → 停 bot → 仅替换 `AsterCore.exe`/`app/`/`plugins/`
- **保留 `accounts/`、`data/`**（配置、账号、插件数据）
- 失败自动回滚（保留上一版备份）
- 主程序与插件可**分别更新**（插件独立小包）

## 8. Backend 适配层（统一接口草案）

内核只认"标准事件 + 标准动作"，每个 backend 负责翻译：

```jsonc
// 标准事件（backend → 内核）
{ "type": "message", "account_id": 740979632,
  "sub_type": "group", "group_id": 123, "user_id": 456,
  "raw": "...", "segments": [ ... ] }

// 标准动作（内核 → backend）
{ "action": "send_message", "account_id": 740979632,
  "target": { "type": "group", "id": 123 },
  "message": [ ... ] }
```

| backend | 说明 | 状态 |
|---|---|---|
| napcat | OneBot v11 WS/HTTP | 现有，首版即支持（默认推荐） |
| lagrange | 内置纯协议直登（自拉子进程） | 可选实验后端，Phase 4 |
| xiaolizi 等第三方 | 私有协议 | 延后（等双后端稳定再议） |

## 10. 风险与合规

| 风险 | 等级 | 应对 |
|---|---|---|
| 非官方协议封号（Lagrange 直登） | 高 | 明确风险提示、仅作可选 B 模式、建议小号；主推 NapCat |
| NapCat/NTQQ 随 QQ 升级失效 | 中 | NapCat 组件可替换、更新器支持组件单独升级 |
| NapCat 再分发许可 | 中 | 默认引导下载而非捆绑，发布前核实许可证 |
| 原生 DLL 崩溃/恶意 | 中 | 子进程隔离 + 沙箱化数据目录 + 签名校验插件 |
| .pyd 版本绑定（CPython 3.12 x64） | 低 | 由统一构建器编译，锁定 Python 版本 |
| 数据迁移（Linux → Windows） | 低 | data 结构保持兼容，文档说明迁移步骤 |
